     Part B: LLM layer

     B0. SDK pin. Run go list -m -versions in the container, then go get 
     github.com/anthropics/anthropic-sdk-go/v2@<latest exact>.
     go.mod/go.sum pin the version.

     B1. internal/llm
     - Client interface: Complete(ctx, Request) (Response, error), Stream(ctx, 
       Request, onText func(string)) (Response, error), Mode() Mode.
       Request{System, User, Schema map[string]any, Effort, MaxTokens}.
       Response{Text, StopReason, Model}.
     - Errors (sentinels + types, per golang-error-handling): ErrRefusal
       (*RefusalError{Category, Explanation}), ErrMaxTokens,
       ErrTimeout, ErrRateLimited (*RateLimitError{RetryAfter}), ErrUnavailable
       (5xx/connection), ErrBadRequest.
     - FromEnv(getenv): no ANTHROPIC_API_KEY means Mock. ANTHROPIC_MODEL
       defaults to claude-opus-5-5. Mode() returns
       "anthropic" or "mock" for the UI badge. getenv is injected so tests never
       touch the real environment.
     - anthropic.go: explicit option.WithAPIKey / WithBaseURL (for tests) /
       WithMaxRetries(2) / WithRequestTimeout.
       Beta endpoint with fallbacks: "default". ANTHROPIC_FALLBACK=off turns it
       off in case the beta isn't enabled for the
       account (added to .env.example). Mid-stream refusal: discard the partial
       text and return ErrRefusal. All text blocks are
       concatenated (a mid-stream fallback continues in a new block).
     - max_tokens: segment 16000 (non-streaming), content 64000 (streaming).
       Thinking counts toward it.
     - mock.go: (a) the no-key demo mock, deterministic: picks up cities and
       keywords from the brief and streams in small chunks;
       (b) Scripted for tests, a queue of Response/error that also records the
       requests.
     - Tests against an httptest fake API: normal response, SSE stream, refusal
       (+stop_details), 429 + retry-after then 200
       (2 calls), persistent 429, 500 (SDK retry then ErrUnavailable),
       max_tokens, timeout. They also check the request body:
       model, effort, output_config.format, fallbacks, no thinking. API key is a
       dummy like test-key.

     B2. segment.Schema() (new segment/schema.go, hand-written, enums from
     vocab): $defs Attribute variants
     (city/language scalar vs list, total_orders integer, total_spent number),
     Event and Group (any_of → $ref Condition only).
     No recursion, no min/max/length/minItems. Drift test (schema_test.go): (1)
     walk the schema for forbidden keywords and $ref
     cycles; (2) generate an instance from every enum combination of every
     variant, which must pass Decode+Validate; (3) every
     (field, op) in defaultFields and every event/op is covered by some variant;
     (4) required = all properties, additionalProperties:false.

     B3. internal/content
     - Content{SMS, EmailSubject, EmailBody} + Schema() (flat, 3 strings) +
       drift test against the JSON tags.
     - Validate: limits 160/80/2000 counted in runes (utf8.RuneCountInString),
       on the template text. Fields must not be empty.
       Only {{first_name}} and {{city}}. Any other {/} is a broken brace. Errors
       are ValidationErrors with paths (sms, email_body...).
     - Render(tpl, Vars): first_name falls back to "Değerli müşterimiz". city
       falls back to "Türkiye" (city is NOT NULL, so this
       practically never fires; recorded in DECISIONS). The prompt tells the
       model not to attach suffixes to {{city}}.
     - SMSInfo(text): GSM-7 basic + extension (extension characters count as 2),
       otherwise UCS-2 (UTF-16 units). Per segment:
       160/153 vs 70/67. Information only. Table test (ü/ö/Ç stay GSM-7, ş/ğ/ı/İ
       switch to UCS-2, emoji, € extension).

     B4. internal/streamjson: Extractor.Write(chunk) []Delta{Field, Text}, a
     byte-level state machine for a flat object of
     string fields. Handles escapes split across chunks (\", \\, \n, \u00e7,
     surrogate pairs) and UTF-8 bytes split across
     chunks. Anything unexpected sends it to a terminal error state (the final
     validation catches it). Tests: every split point for
     the three escapes, table tests. FuzzExtractor: never panics, and for valid
     input the concatenated deltas equal what
     json.Unmarshal returns. Added to make fuzz.

     B5. internal/compose (repair loop, depends only on the llm.Client
     interface)
     - GenerateSegment(ctx, c, brief) (segment.Rule, error): effort low,
       segment.Schema(), Decode+Validate.
     - GenerateContent(ctx, c, in, onEvent): effort medium, streaming, deltas
       from the Extractor. A {Attempt} event at the start of
       each attempt, so the SSE layer can reset. Full json decode +
       content.Validate when the stream ends.
     - Repair: on a validation or JSON error, at most 2 more attempts. Each 
       repair is a new single-turn request: original brief +
       previous output + path: msg lines, all marked as data. Previous thinking
       blocks are never sent back, so the history-binding
       check can't fail. Refusal, max_tokens, timeout, 429 and 5xx are not
       repaired and are returned wrapped. When repairs run out:
       *GenerationError{Stage, Attempts, Problems} + ErrRepairExhausted.
     - Prompts (prompts.go, English instructions, Turkish output): DSL, limits,
       segment.Cities()/Languages(), event types. The
       brief goes in JSON-escaped inside <brief> and is stated to be untrusted
       data that must not be obeyed.
       unsupported_criteria is passed through, not treated as an error.
     - Mock scenario tests (Scripted): valid, broken JSON, over the limit,
       unknown field, unknown variable, unsupported_criteria,
       refusal, max_tokens, fixed on the first repair, not fixed after two
       repairs (3 calls, ErrRepairExhausted). The repair prompt
       carries the paths and the brief is still marked as data.

     B6. DECISIONS.md (repo root, new, one short entry per decision: decision /
     reason / alternative, written in the same commit
     as its code): SDK pin, structured outputs in both calls, hand-written
     schema + drift test + enums in the schema, single-turn repair,
     SDK retry vs repair loop, refusal/max_tokens not repaired, server-side
     fallback default + off switch, max_tokens/effort/timeout
     values, partial parser + fallback plan, rune counting, GSM-7 detection,
     city fallback, mock selection, prompt injection (the real
     safety comes from schema + whitelist + parameterized SQL).
